# Parallel Image Filter and Processor Using Hybrid MPI and OpenMP

**Student:** Sameer Babar (2023-CS-162)
**Course:** Parallel and Distributed Computing Lab, Spring 2026
**Instructor:** Mr. Waqas Ali, Department of Computer Science, UET Lahore

Four implementations (sequential, Pthreads, OpenMP, MPI) of the same
image-filtering pipeline -- Gaussian blur, Sobel edge detection, unsharp-mask
sharpening, and RGB-to-grayscale conversion -- benchmarked on two
complementary real datasets rather than synthetic random pixel data: nine
resolutions of two photographs (4,096 to 18,662,400 px), and a balanced
5,000-photograph subset of Imagenette processed in one batch run per
configuration. See `docs/paper.pdf` for the full writeup (methodology,
design, results, discussion) and `docs/appendices.pdf` for the project
Gantt chart and experimental logbook.

## Directory layout


## Dependencies

| Tool | Used for | Tested version |
|---|---|---|
| `gcc` | compiling sequential / Pthreads / OpenMP | 13.3.0 (Ubuntu) |
| `mpicc` / `mpirun` | compiling/running the MPI version | Open MPI 4.1.6 |
| POSIX shell (`bash`) | `run_experiments.sh` | any Linux/WSL |
| `python3` + `numpy` + `matplotlib` | **optional**, only for `scripts/plot_results.py` | 3.12 / 1.26 / 3.6 |
| `python3` + `Pillow` | **optional**, only for `data/prepare_real_dataset.py` (second real dataset) | 3.12 / 10.2 |

No other libraries are required -- image I/O is a from-scratch binary
NetPBM (PGM/PPM) reader/writer with no external dependency. The dataset is
generated by a pure-C program (`data/input_generator.c`), so the core
experiment pipeline has zero Python dependency; Python is only used to turn
already-measured numbers into plots/tables for the paper.

The two files under `data/base/` (`camera_512.pgm`, `astronaut_512.ppm`)
are real photographs from the scikit-image sample-data distribution
(BSD-3-Clause license) \[van der Walt et al., "scikit-image: image
processing in Python," PeerJ, 2014\], used here as the basis for every
benchmark resolution. They are not random data: convolution filters
produce meaningless output on uncorrelated noise, so all resolutions used
in this project are bilinear resizes of these two real images, generated
by `data/input_generator.c`.

## Second real dataset: Imagenette (5,000 photographs)

In addition to the resized-photograph dataset above, every implementation
supports a `--dataset <dir> <count>` batch mode that loops over a
directory of many real photographs inside one process (or one `mpirun`
session), measuring throughput across the whole batch rather than a
single image. This is used to show how each model behaves at
multi-thousand-image scale rather than multi-million-pixel scale -- see
"Real-world dataset throughput" in `docs/paper.pdf`.

```bash
# 1) One-time download (Apache-2.0, fastai/imagenette, ~99MB):
curl -fSL -o imagenette2-160.tgz \
    https://s3.amazonaws.com/fast-ai-imageclas/imagenette2-160.tgz
tar xzf imagenette2-160.tgz

# 2) Build the balanced 5,000-image benchmark corpus (~500MB, not checked
#    into the repo -- regenerate it with this script, same principle as
#    data/generated/):
python3 data/prepare_real_dataset.py imagenette2-160/train data/real_dataset 5000

# 3) Run any implementation in batch mode:
./scripts/bin/main_seq --dataset data/real_dataset 5000 /tmp/out
./scripts/bin/main_omp --dataset data/real_dataset 5000 /tmp/out 8
mpirun --oversubscribe -np 8 ./scripts/bin/main_mpi --dataset data/real_dataset 5000 /tmp/out
```

`run_experiments.sh` (step 7/7, below) runs this automatically if
`data/real_dataset/` is already prepared, and otherwise prints these same
instructions and skips that one optional stage -- the mandatory
strong/weak/size-sweep experiments never depend on internet access.

## Compilation commands

```bash
gcc   -O3 -Wall -Wextra -o scripts/bin/input_generator data/input_generator.c -lm
gcc   -O3 -Wall -Wextra -o scripts/bin/main_seq        src/sequential/main_seq.c -lm
gcc   -O3 -Wall -Wextra -pthread -o scripts/bin/main_pth src/pthreads/main_pth.c -lm
gcc   -O3 -Wall -Wextra -fopenmp -o scripts/bin/main_omp src/openmp/main_omp.c  -lm
mpicc -O3 -Wall -Wextra -o scripts/bin/main_mpi        src/mpi/main_mpi.c -lm
```

## Running a single program by hand

```bash
# Generate the benchmark dataset once:
./scripts/bin/input_generator data/base/camera_512.pgm data/base/astronaut_512.ppm data/generated

# Sequential baseline:
./scripts/bin/main_seq   data/generated/strong_gray_0003840x002160.pgm data/generated/strong_rgb_0003840x002160.ppm /tmp/out

# Pthreads / OpenMP, with thread count as the last argument:
./scripts/bin/main_pth   data/generated/strong_gray_0003840x002160.pgm data/generated/strong_rgb_0003840x002160.ppm /tmp/out 8
./scripts/bin/main_omp   data/generated/strong_gray_0003840x002160.pgm data/generated/strong_rgb_0003840x002160.ppm /tmp/out 8

# MPI, with process count via mpirun -np:
mpirun --oversubscribe -np 8 ./scripts/bin/main_mpi data/generated/strong_gray_0003840x002160.pgm data/generated/strong_rgb_0003840x002160.ppm /tmp/out
```

Each program prints one CSV-style line per filter to stdout:
`RESULT,<model>,<filter>,<workers>,<width>,<height>,<seconds>`, and writes
the filtered images (binary PGM/PPM) into the given output directory.

## Running the full experiment suite (what the grader should run)

```bash
./scripts/run_experiments.sh
```

This single script, using only relative paths:

1. Compiles all four implementations and the dataset generator.
2. Regenerates the full benchmark dataset (9 strong-scaling resolutions
   from 4,096 to 18,662,400 px, plus 4 weak-scaling resolutions) from the
   two real photographs in `data/base/`.
3. Runs the strong-scaling sweep (fixed 3840x2160 image, 1/2/4/8
   threads-or-processes), the problem-size sweep (8 workers, all 9
   resolutions), and the weak-scaling sweep (rows-per-worker fixed at
   270, 1/2/4/8 workers) -- each filter call timed 3 times internally,
   reporting the minimum (see `TRIALS` in the source) to reduce OS-noise
   jitter.
4. Cross-checks every Pthreads/OpenMP/MPI output at every worker count
   against the sequential baseline byte-for-byte (`cmp -s`) and writes
   `results/raw_outputs/correctness_report.txt`.
5. Writes the combined timing data to `results/raw_outputs/results.csv`
   and per-run logs to `results/raw_outputs/logs/`.
6. (Step 7/7, optional) If `data/real_dataset/` has been prepared (see
   above), runs all four implementations over the full 5,000-image real
   dataset at 1/2/4/8 workers, cross-checks a 50-image subset of that
   batch-mode code path the same way as step 4, and appends a
   `dataset_throughput` block to `results.csv`. If the dataset hasn't
   been prepared, this step is skipped with on-screen instructions
   instead of failing the rest of the script.

To regenerate the paper's figures and timing table from that CSV:

```bash
python3 scripts/plot_results.py
```

This writes `results/figures/strong_scaling_speedup.png`,
`weak_scaling_time.png`, `size_sweep.png`, `exec_time_table.tex`, and --
if the optional real-dataset experiment was run --
`real_dataset_throughput.png` and `real_dataset_throughput_table.tex`
(all embedded in `docs/paper.tex`).

## Notes on environment

Developed and benchmarked on a single physical machine (Intel Core
i5-8365U, 4 cores/8 threads, Ubuntu 24.04.4 LTS under WSL2) -- see the
paper's Experimental Setup section for full hardware/software detail.
Per the course FAQ, all MPI process counts (including `-np 8`) were run
on this one host with `mpirun --oversubscribe`; no multi-node cluster was
available.

## Academic integrity / external code

* The two base images are from scikit-image's sample-data distribution
  (BSD-3-Clause) -- see citation above and in `docs/paper.tex` references.
* The second real dataset is Imagenette (Apache-2.0,
  https://github.com/fastai/imagenette), a real-photograph subset of
  ImageNet distributed by fastai; `data/prepare_real_dataset.py` only
  resizes and reformats these existing real photographs, it does not
  generate any image content.
* `scripts/plot_results.py` and `data/prepare_real_dataset.py` use NumPy,
  Matplotlib, and Pillow respectively for plotting/data-prep only; neither
  implements, times, or otherwise affects any of the four filtering
  implementations being graded.
* All filtering, threading, and MPI code in `src/` and `data/input_generator.c`
  was written for this project; no third-party algorithm implementations
  were used.
